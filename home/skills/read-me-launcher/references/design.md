# README design

Goal: a stranger decides whether to try the project in five seconds, with claims
grounded in inspect output.

## First screen by primary proof

| Primary proof | Above the fold |
|---------------|----------------|
| Code | Pitch + install + working snippet |
| Visual | Pitch + one real screenshot |
| Behavioral | Pitch + install + terminal/workflow proof |
| Operational | Purpose + run commands + ownership |

## Taste tests

- Strip the name: still specific?
- Do install commands exist in the repo?
- Would a skeptical engineer trust the claims?

## Anti-patterns

- Nested fences in HTML (ERROR)
- Documenting scripts that do not exist (ERROR)
- Vibes-only banners with no product proof
- Badge walls / emoji spam
- Treating style prefs (em dashes) as correctness
