# Project notes for agents

Deliberate decisions in this repo - do NOT silently revert them:

- `homebrew.onActivation.cleanup = "zap"` in `configuration.nix` is intentional. It forces the good habit of declaring every Homebrew package in the Nix config instead of installing things ad-hoc, which keeps the machine reproducible. Do not soften it to `uninstall` or `none`. Users are warned about its effect in README.md; this note is for anyone tempted to change the setting itself.
- Never commit `.no-mistakes/` validation evidence to this public repo. `.no-mistakes/` is gitignored; if a validation pipeline stages evidence into a branch, drop it before merging.
- Private-file pattern: for any per-machine secret (Hetzner host, SSH private hosts), keep a gitignored real file (`home/.config/zsh/private-env.zsh`, `home/.ssh/dotfiles.config.private`) alongside a committed `.example` template, and have the relevant `home.nix` module read/Include it by path so Nix never embeds the content in the store. Follow this same shape for the next private value instead of inventing a new mechanism.
- SSH config is fragment-managed, not whole-file-managed: `~/.ssh/config` itself is never a home-manager-generated file (Colima and other tools must be free to rewrite it). `home.nix` only symlinks `home/.ssh/dotfiles.config.public.{darwin,linux}` and `dotfiles.config.private` into `~/.ssh/`, then an activation script idempotently prepends `Include` lines for them. Do not reintroduce a `programs.ssh`-style whole-config approach.
- `home.nix`'s Ubuntu-only `installNativeTools` activation script must not depend on common utilities from the base image or general profile PATH during activation. Any utility an installer shells out to must be both Nix-managed in Linux `home.packages` and present in the script's curated `PATH` export. Each tool's install block must also stay individually fault-isolated (`(...) || echo "WARNING: ..." >&2`) because Home Manager activation scripts run under `set -e`; see `tests/ubuntu-support.test.sh` for the executable regression coverage.
- `home.nix` enables home-manager's native `services.ssh-agent` module on Linux only (`!isDarwin`), so a minimal Ubuntu server (no gnome-keyring/desktop) gets a persistent `systemd --user` ssh-agent that keeps a key unlocked across shells until logout/reboot, with `SSH_AUTH_SOCK` auto-wired into `programs.zsh`. Do not hand-roll a shell-rc `eval $(ssh-agent)` mechanism instead - the native module already does this and is covered by `tests/ubuntu-support.test.sh`. Left disabled on macOS since launchd + Keychain (`UseKeychain`) already provide this for free there.
- `tools.nix` is the single source of truth for every managed CLI tool and GUI app (`scope`, `platform`, `updatePolicy`, optional `isCask`/`brewName`/`nixName` - field semantics and two-stage selection logic documented in README.md under "Package metadata"). `tool-selection.nix` holds the shared `isEnabled`/`isForCurrentPlatform`/`useNix`/`useHomebrew`/`useNative` predicates, parameterized by `currentPlatform`; don't hand-maintain separate brew/cask/Linux package lists. `configuration.nix` (macOS) hardcodes `currentPlatform = "macos"`; `home.nix` (macOS + Ubuntu, via `flake.nix`'s `darwinConfigurations.mac` and `homeConfigurations."<user>@<system>"` outputs) derives it per-output from `pkgs.stdenv.isDarwin` instead, since a single file-level constant can't be right for both targets at once. `scope = "personal"` entries are gated by one shared `usePersonalSetup` module argument (required, no default - nix-darwin doesn't honor plain Nix argument defaults for custom module args, so both `specialArgs` and the Linux outputs' `extraSpecialArgs` in `flake.nix` must always supply it). Any `home.nix` line shared between the macOS and Ubuntu branches (a path, an OS-specific alias) must be explicitly gated per platform - an ungated edit that looks harmless on macOS still changes `darwinConfigurations.mac`'s evaluated derivation; `tests/ubuntu-support.test.sh` pins that drvPath and fails if it moves. `useNative` (fast-moving `platform=all` tools on Ubuntu: claude-code/codex/herdr/skills/pi-coding-agent) is correctly selected but has no actual installer wired up yet.
