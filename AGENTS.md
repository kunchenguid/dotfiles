# Project notes for agents

Deliberate decisions in this repo - do NOT silently revert them:

- `homebrew.onActivation.cleanup = "zap"` in `configuration.nix` is intentional. It forces the good habit of declaring every Homebrew package in the Nix config instead of installing things ad-hoc, which keeps the machine reproducible. Do not soften it to `uninstall` or `none`. Users are warned about its effect in README.md; this note is for anyone tempted to change the setting itself.
- Never commit `.no-mistakes/` validation evidence to this public repo. `.no-mistakes/` is gitignored; if a validation pipeline stages evidence into a branch, drop it before merging.
- Private-file pattern: for any per-machine secret (Hetzner host, SSH private hosts), keep a gitignored real file (`home/.config/zsh/private-env.zsh`, `home/.ssh/dotfiles.config.private`) alongside a committed `.example` template, and have the relevant `home.nix` module read/Include it by path so Nix never embeds the content in the store. Follow this same shape for the next private value instead of inventing a new mechanism.
- SSH config is fragment-managed, not whole-file-managed: `~/.ssh/config` itself is never a home-manager-generated file (Colima and other tools must be free to rewrite it). `home.nix` only symlinks `home/.ssh/dotfiles.config.public.{darwin,linux}` and `dotfiles.config.private` into `~/.ssh/`, then an activation script idempotently prepends `Include` lines for them. Do not reintroduce a `programs.ssh`-style whole-config approach.
- `tools.nix` is the single source of truth for every managed CLI tool and GUI app (`scope`, `platform`, `updatePolicy`, optional `isCask`/`brewName`/`nixName` - field semantics and two-stage selection logic documented in README.md under "Package metadata"). `tool-selection.nix` holds the shared `isEnabled`/`isForCurrentPlatform`/`useNix`/`useHomebrew`/`useNative` predicates, parameterized by `currentPlatform`; don't hand-maintain separate brew/cask/Linux package lists. `configuration.nix` (macOS) hardcodes `currentPlatform = "macos"`; `home.nix` (macOS + Ubuntu, via `flake.nix`'s `darwinConfigurations.mac` and `homeConfigurations."<user>@<system>"` outputs) derives it per-output from `pkgs.stdenv.isDarwin` instead, since a single file-level constant can't be right for both targets at once. `scope = "personal"` entries are gated by one shared `usePersonalSetup` module argument (required, no default - nix-darwin doesn't honor plain Nix argument defaults for custom module args, so both `specialArgs` and the Linux outputs' `extraSpecialArgs` in `flake.nix` must always supply it). Any `home.nix` line shared between the macOS and Ubuntu branches (a path, an OS-specific alias) must be explicitly gated per platform - an ungated edit that looks harmless on macOS still changes `darwinConfigurations.mac`'s evaluated derivation; `tests/ubuntu-support.test.sh` pins that drvPath and fails if it moves. `useNative` (fast-moving `platform=all` tools on Ubuntu: claude-code/codex/herdr/skills/pi-coding-agent) selects all five, but only `herdr` has an installer actually wired up: its `tools.nix` entry sets `nativeInstallUrl` (herdr's own non-interactive `install.sh`), and `tool-selection.nix`'s `nativeInstallTools` filters `useNative`'s output down to entries with that field set, which `home.nix`'s `installNativeTools` activation script runs (skipping if already installed) with `~/.local/bin` added to `home.sessionPath`. The other four don't set `nativeInstallUrl` - their installers are interactive or rewrite shell rc files themselves (fighting home-manager's declarative zsh config) - so `useNative` still classifies them correctly but nothing installs them; see `tests/ubuntu-support.test.sh`'s `test_linux_herdr_native_install_wired` for the regression coverage and `home.nix`'s comment on `installNativeTools` for why the mechanism isn't force-fit onto them.
